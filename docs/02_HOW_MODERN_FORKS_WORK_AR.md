# كيف تُهندس وتُبنى مشتقات المتصفحات الحديثة (How Modern Forks Work)

يعتقد الكثير من المطورين المبتدئين أن عمل "Fork" لمتصفح يعني فتح مستودع كروميوم أو فايرفوكس وعمل `git fork` على GitHub ورفع الكود!
هذا مستحيل عملياً؛ فمستودع كروميوم يتجاوز 100 جيجابايت وملايين الملفات، وGitHub يرفض مستودعات بهذا الحجم.

فكيف تنجح مشاريع مثل **Brave**, **Ungoogled-Chromium**, **Thorium**, **LibreWolf**, **Zen Browser**؟

---

## سر الـ "Patch Repository Architecture"

جميع هذه المشروعات تعتمد على معمارية تسمى **"مستودع الباتشات الخفيف" (Lightweight Patch Repository)**:

```
[مستودعك على GitHub] (حجمه عدة ميجابايت فقط)
   ├── args.gn أو mozconfig       <-- إعدادات وتعطيل التيليميتري
   ├── patches/                   <-- ملفات .patch لتعديل كود C++
   │    ├── 0001_disable_telemetry.patch
   │    ├── 0002_custom_branding.patch
   │    └── 0003_custom_features.patch
   ├── scripts/                   <-- سكربتات الأتمتة (Fetch, Patch, Build)
   └── custom_cpp_subsystems/     <-- كود C++ الخاص بميزاتك الإضافية
```

---

## دورة حياة المشروع وبناء الإصدارات (The Workflow):

1. **مراقبة الإصدارات المستقرة (Upstream Monitoring):**
   - تراقب إطلاق الإصدارات المستقرة الرسمية من كروميوم (Chromium Stable Tags) أو فايرفوكس (Firefox ESR / Release).

2. **الجلب الآلي للكود النظيف (Clean Fetch):**
   - سكربت البناء يقوم بتنزيل كود المصدر النظيف عبر أدوات موزيلا أو جوجل الرسمية (`depot_tools` أو `mach`).

3. **تطبيق الباتشات (Applying Patches):**
   - يقوم السكربت بتشغيل:
     ```bash
     git apply patches/*.patch
     ```
   - في غضون ثوانٍ، يتم تعديل ملفات C++ المستهدفة (تغيير اسم البرنامج، إزالة كود الاتصال بخوادم التتبع، حقن دوال C++ الخاصة بك).

4. **الترجمة والتحزيم (Compilation & Packaging):**
   - يتم تشغيل `ninja` أو `mach build` لتوليد ملفات التثبيت (`.exe`, `.deb`, `.dmg`, `.AppImage`).

---

## كيف تحافظ على استمرار المتصفح مع التحديثات الأمنية المستمرة؟

تصدر موزيلا وجوجل تحديثات أمنية دورية (كل 2 إلى 4 أسابيع). كيف تواكبها دون أن ينهار مشروعك؟
- **فصل الكود الخاص بك عن كود النواة:** كلما كانت ميزاتك المخصصة مبنية كطبقة مستقلة (Modular Subsystems) ترتبط بالنواة عبر واجهات موحدة (APIs / Interceptors / Hooks)، كان من السهل إعادة تطبيق الباتشات (`git rebase` أو `git apply`) دون تعارضات.
- هذا بالضبط هو التصميم المعماري الذي وضعناه لك في هذا المستودع!
